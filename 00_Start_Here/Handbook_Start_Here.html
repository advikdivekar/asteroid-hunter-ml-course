01. Project overview

The idea in plain words

Telescopes photograph the same patch of sky again and again. Stars stay put. Asteroids move, so over a few minutes an asteroid is a dot that creeps in a straight line. Surveys like the Zwicky Transient Facility (ZTF) take millions of images, and almost all the dots they flag are junk (bad image subtraction, cosmic rays, noise). Our project builds a pipeline that:

  1. takes ZTF's difference images (tonight's picture minus an old picture of the same sky, so everything that did not change disappears),
  2. finds every blob left over,
  3. uses a neural network to decide which blobs look like a real moving object (not junk),
  4. links blobs from different frames into straight-line tracks,
  5. uses a second model (gradient-boosted trees) to score each track,
  6. compares the tracks with the catalogue of known asteroids, and keeps what is unknown for a person to examine.

It was inspired by an online post where someone found a planet candidate in old Kepler telescope data using AI-assisted code (we checked that post: the signal belongs to an already confirmed planet, see project/docs/kepler_post_check.md).

Why machine learning is needed here

  • One night of one CCD quadrant (5 frames) gives about 36,000-41,000 blobs, and only about 3% are real (validation nights: 3.2%). Hand-written rules for "looks like a real object" fail because junk comes in many shapes (dipoles, spikes, edges, ghosts).
  • A CNN learns those shapes from labelled examples; a rule-based filter could not.
  • The tracklet classifier combines about 17 numbers per track (speed, straightness, steady brightness, what the CNN thought, ...) better than any single threshold.
  • Everything physical (matched filtering, linking by straight lines, shift-and-stack) is not ML: it is search and statistics. Knowing which part needs learning and which does not is part of good ML design.

What we are careful NOT to claim

  • No discovery. One faint object in a related two-night study passes every check we have (orbit fit, noise tests, no catalogue match). It still needs a human reading the images and the Minor Planet Center's process. Nothing has been reported as a discovery.
  • The best depth number (22.1) is for one night and one CCD quadrant.
  • Our "real" labels come partly from simulation (planted fakes). We checked that fakes look like real asteroids (a classifier cannot tell them apart: AUC 0.47) but that is a check on certain features, not a proof.

The story of how it got better (good for the viva)

  1. v1: CNN + XGBoost on single frames. Looked great (AP 0.999 for tracklets). The scoreboard showed the truth: depth only ~20.5.
  2. We measured where asteroids were lost: at linking, not at the classifier. Relaxing linking found 11% more asteroids but created ~1,500 chance tracks per night (these became the hard negatives).
  3. A bigger multi-frame CNN tied the simple XGBoost model, so we kept the simple one (v4).
  4. 3x more training data (v5) did not help: the limit is how many photons one 30-second frame holds.
  5. Therefore we added the deep search (adding frames along a trial motion): +0.7 magnitude.
  6. Along the way, real bugs were found by checking results against reality: SkyBoT catalogue positions were ~2.9 arcsec off; telescope pointing shifts between exposures; a feature that wrongly flagged 22% of real tracks. Each was fixed and a test written.

02. Domain primer: the astronomy you need (no prior astronomy assumed)

You do not need to be an astronomer. You need about twelve ideas, each explained so you can say it in your own words in a viva.

1. What an asteroid is, and why it shows up as a moving dot

Asteroids are rocky bodies orbiting the Sun (most between Mars and Jupiter, the main belt). From Earth, stars are so far away that they appear fixed. An asteroid is close enough that it visibly moves against the stars: tens of arcseconds per hour for a typical main-belt asteroid near opposition (our data: 28-48 arcsec per hour). An arcsecond is 1/3600 of a degree. Over the ~30 minutes of 5 consecutive exposures, an asteroid moves in a nearly straight line at a nearly constant speed. That is the physical fact the whole linking stage relies on.

2. The telescope and the survey

ZTF (Zwicky Transient Facility) photographs the northern sky with a camera at Palomar Observatory (California). The camera has 16 CCD chips; each chip is read out in 4 quadrants of about 3072 x 3080 pixels. One pixel is about 1.01 arcseconds. A standard exposure lasts 30 seconds. Images come in filters (we use r band, "zr"). The data is public through IRSA (a NASA/IPAC archive).

A unit in our project = one field (a patch of sky) + one CCD + one quadrant + one night. Example: 000618_c03_q4_2019-02-08 = field 618, CCD 3, quadrant 4, night 8 Feb 2019.

3. The four files per exposure

File What it is
science image the picture itself (about 38 MB)
reference image a deep picture of the same sky built from many old exposures (we recompute it as science minus difference)
difference image science minus the (blurred, aligned) reference: static things cancel
mask 16 yes/no flags per pixel: saturated, dead, cosmic ray, ghost, ...
PSF the blur shape of a point source in the difference image

4. Difference imaging: the key trick

difference = science - reference. Stars, galaxies and the sky glow are the same in both and cancel. What remains: new or moving things (positive blobs, what we want), faded things (negative blobs, ignored), imperfect cancellation of bright stars (dipoles), cosmic rays, and noise. Most blobs in a difference image are junk, which is exactly why a classifier is needed.

5. Noise, sigma, and signal-to-noise (SNR)

Every pixel has random noise. We measure its spread (sigma) robustly (with the median absolute deviation, MAD, so bright blobs do not fool it: sigma = 1.4826 x median(|x - median|)). A blob "5 sigma" bright is 5 times the noise level. SNR = measured flux divided by its uncertainty. With pure noise, about 1 pixel in 3.5 million exceeds +5 sigma, so a 5-sigma blob is unlikely to be chance, unless you looked in many places (see 12).

6. The PSF (point spread function)

A star or asteroid is a point of light, but the atmosphere and optics blur it into a small round blob (about 2 pixels wide for us). The blur shape is the PSF. Knowing it lets us do matched filtering: smooth the image with the blur shape, which makes faint point-like sources stand out of random noise.

7. Magnitudes (how astronomers measure brightness)

A magnitude is a log brightness scale where bigger = fainter. 5 magnitudes = a factor of 100 in brightness. So one magnitude is a factor of about 2.5. Our single-frame limit is about magnitude 20.5-21.4; the deep search reaches about 22.1, which is 0.7 magnitudes fainter, a factor of about 1.9 in brightness. The faintest star the naked eye can see is about magnitude 6, so these asteroids are about a million times fainter (15 magnitudes = a factor of 10^6).

7b. Opposition

At opposition the asteroid is opposite the Sun in the sky: closest to Earth and brightest, and there are the most of them near the ecliptic (the plane of the planets). Our test night, 2019-02-08, was near opposition, so it is both the most asteroid-rich and a deliberate "distribution shift" from the training nights.

8. WCS (sky coordinates) and why pointing matters

The WCS converts pixel positions to sky positions (RA, Dec). The telescope does not point at exactly the same pixels in consecutive exposures (shifts up to 12 pixels). An asteroid moves in a straight line on the sky, not in each frame's pixels. So we put every blob on frame 1's common sky grid before linking. Forgetting this was our biggest bug.

9. Known versus unknown asteroids

Hundreds of thousands of asteroids are catalogued. The Minor Planet Center (MPC) keeps the official list. We look them up with SkyBoT (a service that predicts where known objects are) and JPL Horizons (NASA's very accurate ephemeris). We measured SkyBoT positions to be about 2.9 arcsec (2.7 px) off, while Horizons is within 0.26 px. Almost everything we detect is already known; only objects matching nothing are candidates.

10. Tracklet

A tracklet = a set of detections in different frames that line up as one moving object. It needs at least 3 of the 5 frames, a straight line within 1.5 pixels, and a speed between 8 and 120 arcsec/hour.

11. Injection-recovery and completeness

We cannot know which real asteroids are in an image, so we plant fake asteroids (known brightness, speed, position) into the real images, run the normal pipeline and count how many come out. The fraction recovered, as a function of brightness, is the completeness. "50% completeness at magnitude 20.5" means: half of the fakes of that brightness are found. This is the standard method in survey astronomy.

12. Look-elsewhere effect (why we need a 6-sigma cut in the deep search)

If you test thousands of places or motions, some random noise will reach 5 sigma by chance. In the deep search we try 4,888 motions at every pixel, so noise alone produced 6,179 peaks at 5 sigma but only 44 at 6 sigma (on a pure-noise test). So we require 6 sigma. This is the same logic as multiple-testing correction in statistics.

Two more terms you will hear

  • Dipole: a bright half next to a dark half, the typical leftover of a bright star that did not subtract perfectly.
  • Ghost / bleed trail: optical or detector artifacts (a bright star's charge spilling along a CCD column). Bleed trails line up along columns and can fool a fast-object search; we found six of seven fast "tracks" we inspected were such artifacts.

03. ML primer: the ideas we used, tied to the syllabus

Each idea has three lines: what it is, where it appears in our project, the syllabus session it matches (from the course policy document). If you can explain these in your own words, you can pass a viva on any part.

A. The problem setting

Supervised learning: learn a function from examples with known answers. Ours: the CNN learns real/bogus from labelled stamps; XGBoost learns real/bogus tracklets from labelled tracklets. Syllabus: types of learning, supervised vs unsupervised. Classification vs regression: classification predicts a category (real/bogus), regression a number. Ours: classification; one small regression (a straight-line fit from stack SNR to magnitude in the deep search: mag = 26.25 - 5.23 log10(SNR)). Syllabus: linear regression. Features and labels: a feature is a number measurable on new unlabelled data; the label is the answer. Ours: mag and true_rate existed only for planted fakes, so they were illegal features (target leakage). Syllabus: ML requirements (CO1).

B. Models

Logistic regression: p = sigmoid(w.x + b), trained by minimising log-loss. Ours: the baseline on 6 numbers per detection (AP 0.780), and in the model comparison on tracklets. Syllabus: logistic regression, hypothesis, cost function. Gradient descent: repeat w <- w - learning_rate x gradient. Ours: written by hand in numpy in notebooks/neural_networks.ipynb, then Adam in PyTorch for the CNN. Syllabus: gradient descent, cost function. Neural network: layers of "weighted sum, then non-linearity". Without the non-linearity, stacked layers collapse into one linear function. Ours: the CNN. Syllabus: NN hypothesis, cost, activation functions. Backpropagation: the chain rule applied from the output back, so one sweep gives every gradient. For sigmoid + cross-entropy the output error is simply p - y. Ours: coded by hand and checked numerically (matches to 8 decimals). Syllabus: backpropagation. Convolutional neural network (CNN): filters (3x3 grids of learned weights) slide across an image looking for a local pattern; pooling shrinks the image so deeper filters see larger areas. Ours: 5 convolution layers over 3 stacked pictures (science, reference, difference); 72,145 weights. Syllabus: neural networks (applied). Decision tree -> random forest -> gradient boosting: a tree asks yes/no questions; a forest averages many random trees (bagging, lowers variance); boosting builds trees one after another, each correcting the errors so far. Ours: XGBoost on 17 numbers per tracklet (300 trees, depth 3, learning rate 0.05). Syllabus: trees, bagging, random forests, boosting.

C. Making models behave

Overfitting: the model memorises noise; training error falls, validation error rises. Ours: a demo on 40 points (validation loss lowest at step 22 then climbs), and early stopping in the CNN. Syllabus: bias and variance, evaluating a hypothesis. Regularisation: anything that stops the model fitting noise: a penalty on large weights (L2 in logistic regression, strength C), dropout (0.3 in the CNN head), early stopping (patience 4), subsampling (XGBoost uses 80% of rows and columns per tree), data augmentation (random rotations and mirrors). Syllabus: regularization (CO2). Feature scaling / normalisation: put numbers on a comparable scale. Ours: per-stamp robust normalisation (x - median) / (1.4826 MAD), clipped to [-10, 50]. Trees need no scaling. Class imbalance: real objects are about 3% of detections. We balanced training (all real + 5 bogus per real = 16.7% real) but kept validation realistic. Side effect: raw probabilities are inflated; fix with base-rate adjustment or isotonic calibration.

D. Evaluating honestly (the heart of "model evaluation", worth 3 marks)

Train / validation / test: train fits the model; validation chooses settings and thresholds; test is opened once. Ours: split by night, decided in a config file before modelling. Syllabus: train-validation-test. Data leakage: information at training time that will not exist at use time. Four forms we found: target leakage (mag), group leakage (all tracklets from 4 images), shortcut learning (random bogus tracklets 222+ px off a line), distribution shift (test night sharper). Evidence: accuracy 100% -> 50% -> 99% depending on the test data. Cross-validation: repeat train/test over several splits. Ours: GroupKFold by night (never random rows). Cross-fitting is the same idea used so a second model does not see over-confident first-model scores. Confusion matrix, precision, recall, false-positive rate: see 04_Satvik/diagrams/confusion_metrics.svg. Syllabus: error metrics for skewed classes, precision/recall trade-off. Accuracy paradox: "always bogus" scores 96.8% accuracy and finds nothing. With rare positives use recall, precision and the precision-recall curve (average precision). ROC AUC looked excellent (0.95) when precision at useful recall was under 20%. Syllabus: ROC curves. Threshold / operating point: pick the cut on validation to keep 90% of real objects, then count false alarms. Calibration: do scores mean probabilities? (reliability plot; isotonic regression; Bayes base-rate correction). Error analysis: look at the model's most confident mistakes. Ours: the CNN's top "bogus" scores were known asteroids -> exposed a 2.9 arcsec catalogue offset (label error). 9 "false positives" on the test night were real known asteroids our labels missed. Syllabus: error analysis. Completeness curve (injection-recovery): the domain's version of a recall-by-condition plot (recall vs brightness). Adversarial validation: train a classifier to tell fakes from real; AUC 0.47 means it cannot -> fakes are realistic. Fair comparison: compare models at the same false-alarm level, not at each one's own threshold.

E. Ideas from the research side

Stacking: one model's output is another's input (CNN scores are features for XGBoost). Ensembling: averaging the two models gave only a tie. Occam's rule: when models tie, use the simplest (a multi-frame CNN tied XGBoost; we kept XGBoost). Negative results are results: 3x more data did not help; the limit was physics (photons in one frame), not model size. Look-elsewhere effect / multiple testing: pick the best of 4,888 trials and noise looks significant. Calibrate on pure noise (6 sigma), and run a null test (shuffle the frame times; real movers stop lining up; we got 0 false tracks).

F. Syllabus topics we did NOT use (be honest about them)

Linear regression as a main model, polynomial regression, the normal equation, SVMs, PCA, k-means, hierarchical clustering, regression trees. See 04_Course_Mapping.md for how to cover them with small extra experiments if your faculty expects them. We touch anomaly detection only in spirit: "tracks that match nothing in the catalogue" is an anomaly filter, but it is a catalogue lookup, not a learned anomaly model.

5. What we have done, in one paragraph (for the report's abstract)

We implemented an end-to-end machine-learning pipeline for detecting moving objects in archival ZTF difference images. We built reproducible data acquisition split by night, generated labels by injection-recovery and catalogue matching and audited their quality, trained a convolutional real/bogus classifier (average precision 0.899 on validation, 0.938 on the test night, 4.6x fewer false alarms than a logistic-regression baseline), linked detections into tracks and scored them with gradient-boosted trees, and evaluated the whole system with a scoreboard on held-out nights using planted asteroids (depth of about 20.5 magnitudes for single frames, 21.4 after improving linking, 22.1 with a shift-and-stack deep search). We report negative results honestly (a multi-frame CNN tied XGBoost; three times more training data did not help) and make no discovery claim.

06. Whole-project viva: questions every member must answer

How to use: take turns asking each other, answer out loud in 30-60 seconds, then read the model answer. The model answers are short on purpose; add your own example from your part.

The basics

Q1. What does the project do, in one sentence? It is an ML pipeline that searches archival ZTF telescope images for moving objects (asteroids), separates real ones from junk with a CNN and a tree model, checks them against the catalogue of known asteroids, and measures honestly how deep and how reliable the search is.

Q2. Why difference images? Subtracting an old reference of the same sky from tonight's picture cancels stars, galaxies and sky glow, so only new or moving things remain. That shrinks the search from about 1,950 sources to a few hundred strong ones per frame.

Q3. Why does the project need machine learning at all? Most blobs in a difference image are junk, in many shapes (dipoles, cosmic rays, edges, noise); only about 3% are real. Hand-written rules cannot capture all those shapes. A CNN learns them from labelled examples, and gradient-boosted trees combine many weak track-level clues better than a single cut. The rest of the pipeline (matched filtering, linking, shift-and-stack) is physics and search, not learning.

Q4. What are the two ML models, and what are their inputs and outputs? (1) A CNN: input a 3 x 31 x 31 stamp (science, reference, difference), output p(real) for one blob. (2) XGBoost: input 17 numbers describing a track (speed, straightness, brightness steadiness, CNN scores, forced photometry...), output a score for the whole track.

Q5. What is a unit and what is a tracklet? A unit is one field + CCD + quadrant + night. A tracklet is a set of detections in different frames that lie on a straight line at a plausible asteroid speed (at least 3 of 5 frames, within 1.5 px of the line, 8-120 arcsec/hour).

Data and honesty

Q6. Why split by night and not randomly? Frames from one night share the same stars, noise and artifacts. A random split would put near-copies in train and test and inflate scores. Splitting by night, decided in a config file before modelling, keeps the test honest.

Q7. Give an example of data leakage from your own project. Our first dataset had mag and true_rate columns that existed only for planted fakes, so "is mag missing?" equalled the label. Also, the random bogus tracklets were 222+ pixels off a line while real ones were within 2.6 px, so a one-line rule scored 100%. Trained on that data, a model got 50% (a coin flip) on realistic near-miss tracklets and 99% when trained on realistic data.

Q8. How do you get labels when the sky is not labelled? Three sources: planted fake asteroids (perfect labels, but only as real as the simulation), known asteroids from catalogues (real, but fewer, positions from JPL Horizons), and everything else called bogus (with a little label noise, because it includes undiscovered real objects).

Q9. How do you know your fakes look like real asteroids? A classifier trained to tell fakes from real known asteroids (matched in brightness, cross-validated by night) scored AUC 0.46-0.48, where 0.5 means indistinguishable. Also real asteroids and fakes both fade out between magnitudes 20.5 and 21.5.

Q10. What was the biggest bug and how was it found? The telescope pointing shifts between exposures (up to 12 px). We linked blobs in each frame's own pixel coordinates, so real asteroids did not line up while fakes (planted straight in pixel coordinates) did. Real asteroids all showed the same residual pattern, which pointed at a per-frame error. Fix: put every blob on frame 1's sky grid before linking; real residuals fell from about 2.5 px to 0.05-0.47 px. Lesson: test the simulation against real objects, not only against itself.

Models and metrics

Q11. Why not just report accuracy? Only about 3% of blobs are real, so "always bogus" scores 96.8% accuracy while finding nothing. We report recall (how many real objects we keep), precision (how pure the flagged set is), false alarms per frame and average precision.

Q12. Why is a precision-recall curve better than ROC here? ROC's x-axis divides by all bogus (65,000), so hundreds of false alarms look like a tiny step: ROC AUC was 0.95 while precision at useful recall was under 20%. Precision divides by the number of alerts, so it shows directly how polluted the output is.

Q13. How did you choose the thresholds? On the validation nights only, never on test: the CNN cut keeps 95% of real detections; the tracklet cut keeps 95% of real tracklets. Fixing recall first and then counting false alarms follows the cost argument: a missed asteroid is a lost discovery, a false alarm costs one minute of a person's time.

Q14. What is cross-fitting and why did you need it? The tracklet model uses the CNN's scores as features. A CNN scoring nights it trained on is over-confident, and the tracklet model would learn that. So training nights are scored by CNNs trained on other nights (4 folds of 2 nights), and validation/test nights by the final CNN. It is stacking without leakage.

Q15. How do you prevent overfitting? CNN: dropout 0.3, data augmentation (rotations and mirrors), early stopping on validation AP with patience 4. XGBoost: shallow trees (depth 3), small learning rate (0.05), 80% row and column subsampling. Everything is judged on nights the model never saw.

Q16. The tracklet classifier scores AP 0.999. Is it great? No. That number is saturated: 96% of tracklets in that data are real because we plant 300 fakes per night, the opposite of the real sky. It cannot show improvement. What matters is depth, known asteroids recovered, and bogus tracklets per night on held-out nights.

Results and evaluation

Q17. What does "50% completeness at magnitude 20.5" mean? Plant fake asteroids of known brightness; at magnitude 20.5 the system recovers half of them. Bigger magnitude is fainter, so a deeper system has a bigger number.

Q18. How did the system improve from v1 to v4, and why? v1 reached depth about 20.5. We measured where asteroids were lost: at linking, not at the classifier. Relaxing linking found 11% more but created about 1,500 chance tracks per night, which became hard negatives; adding two physics features (static neighbours, forced photometry) controlled them. Depth on the test night rose to 21.4. A multi-frame CNN only tied the simple XGBoost, so we kept XGBoost.

Q19. Why did 3x more training data (v5) not help? At equal false-alarm levels v4 was equal or slightly better. The system is limited by how many photons one 30-second frame holds, so more examples cannot reveal what is not in the image. That is why the deep search, which adds frames, gained +0.7 magnitude, more than any model change.

Q20. What is the deep search and why does it work? Shift the frames along a trial motion so a moving object lands on the same pixel and add them. The signal adds N times but the noise only sqrt(N) times, so 8 frames gain about 2.8x, +1.1 magnitudes. We try 4,888 motions on the GPU. Because we pick the best of thousands of trials, noise alone reaches 5 sigma (look-elsewhere effect), so we require 6 sigma, and a null test with shuffled frame times produced 0 false tracks.

Q21. How do you know the deep search is not finding noise? Calibrate the threshold on pure noise; a null test (shuffle the frame times so real movers no longer line up) gives 0 false tracks after the velocity-consistency cut; the cut also kept 20 of 20 known asteroids. Injection-recovery gives 94-100% recovery at magnitude 21.4-21.9.

Q22. Why compare models at the same false-alarm level? A rule like "95% recall on validation" lands on different points of each model's trade-off curve. v5 looked 0.8 mag worse at its own threshold, but at matched alarms it tied v4. Fair comparison means the same operating point.

Limits and ethics

Q23. Did you discover an asteroid? No. The system recovers known asteroids reliably to about magnitude 21. One faint object in a related two-night study passes every check we have (an orbit fit, noise tests, no catalogue match), but that is not a discovery: it needs a human to read the stamps and the Minor Planet Center's process. Nothing has been reported.

Q24. What are the main limitations? Depth is capped by single frames (the deep search helps on one quadrant of one night); the training data covers one field mostly; "real" labels come partly from simulation; catalogue positions have errors; the test night is no longer perfectly untouched because real bugs were fixed after looking (so a separate holdout night exists); and "unknown" only means "not in the catalogue we queried".

Q25. What would you do with more time? Evaluate on more fields and nights; try an SVM and clustering of the "bogus zoo" for the course syllabus; add a learning curve; run the deep search on more nights; get an independent confirmation from another survey.

Q26. How reproducible is it? Configs hold every setting; the night split is in a config; random seeds are [project seed, night date]; model versions are bundles with the commit and nights used; archive answers and known-asteroid lookups are cached; about 150 offline tests; environment.yml pins the software.

Q27. How did you use AI in this project? (answer truthfully; see 07_AI_Use_and_Integrity.md) The project was developed with an AI coding assistant (Claude) under Advik's direction, including code, documentation and diagrams; each of us then re-ran and studied our part. We declare this as the course policy requires. Be ready to show that you understand your own part without notes.

Where the course topics are

Q28. Which syllabus topics does the project use? Logistic regression (baseline), gradient descent and backpropagation (from scratch), neural networks/CNN, regularisation (L2, dropout, early stopping), train/validation/test, error analysis and skewed-class metrics, decision trees, bagging, random forests and boosting, ROC. Not used: SVM, PCA, clustering, normal equation (we say so openly).

Q29. If I gave you 3 minutes and a whiteboard, how would you draw the pipeline? Data (IRSA, split by night) -> difference image -> detect blobs -> stamps -> CNN -> keep blobs above a cut -> link into tracks on the sky grid -> 17 features -> XGBoost -> cross-match with known asteroids -> unknown candidates -> a person. Underneath: planted fakes and held-out nights measure every stage; the deep search adds frames along trial motions for fainter objects.

Q30. What did you personally learn that surprised you? (prepare your own answer) Good examples: a model's most confident "mistakes" revealed a labelling error; a near-perfect AP meant nothing; adding data did not help; the evaluation design mattered more than the model.

08. Glossary

Term Meaning (plain words)
Accuracy fraction of all predictions that are right; misleading when one class is rare
Adam a gradient-descent variant that adapts each weight's step size; our optimiser
Adversarial validation train a classifier to tell two datasets apart; if it cannot (AUC 0.5) they are alike
Anomaly detection finding items that do not fit the known pattern; our "unknown" tracks are anomalies by catalogue lookup
Arcsecond ("") 1/3600 of a degree; one ZTF pixel is about 1.01 arcsec
Asteroid (main belt) rocky body orbiting the Sun, mostly between Mars and Jupiter
Augmentation making extra training examples by rotating/mirroring; sky has no "up"
Average precision (AP) area under the precision-recall curve; a single summary for rare positives
Backpropagation chain rule from output back to every weight; gives all gradients in one sweep
Bagging train many models on random samples and average them (random forest)
Base rate how common the positive class really is (about 3% real)
Bias / variance systematic error vs sensitivity to the training sample; underfit vs overfit
Bleed trail charge from a saturated star spilling along a CCD column; causes false fast tracks
Boosting trees built one after another, each fixing the previous errors (XGBoost)
Bogus a detection that is not a real moving object (artifact, noise...)
Bundle (model) a saved version: CNN + tracklet model + thresholds + provenance (models/v4)
Calibration making scores mean real probabilities (reliability plot, isotonic regression)
CCD / quadrant a camera chip / one quarter of a chip (about 3072 x 3080 px)
Class imbalance one class is much rarer than the other
CNN convolutional neural network: filters slide over an image to find local patterns
Common grid frame 1's pixel grid; every blob is projected onto it before linking
Completeness fraction of planted fakes recovered (recall by brightness)
Confusion matrix counts of true/false positives and negatives
Cross-fitting scoring each fold with a model that did not train on it, so stage 2 sees honest scores
Cross-validation (GroupKFold) repeated train/test by groups (nights), never by random rows
Deep search shift-and-stack along trial motions to reach fainter than one frame
Depth the brightness (magnitude) where 50% of fakes are recovered
Difference image science minus reference: only new things remain
Dipole bright half beside dark half: imperfect subtraction of a bright star
Dropout randomly switching off neurons during training to reduce overfitting
Early stopping stop training when validation performance stops improving; keep the best epoch
Ephemeris a table of where an object should be at given times
FITS the standard astronomical image file format
Forced photometry measuring flux at a predicted position even where nothing was detected
Gradient descent repeatedly move weights against the gradient of the loss
Holdout night a night never used for choosing anything; opened only to write one number
IRSA NASA/IPAC archive that serves the ZTF data
Injection-recovery plant fakes, run the pipeline, count what comes out
Isotonic regression monotone curve used to calibrate scores
KD-tree data structure for fast nearest-neighbour lookups
Leakage information at training time that will not exist at use time (target, group, shortcut, shift)
Linking joining blobs from different frames into one straight-line track
Log-loss (cross-entropy) the loss for probabilities: confident and wrong costs a lot
Look-elsewhere effect testing many places makes chance peaks likely; raise the threshold
Magnitude log brightness scale: bigger is fainter; 5 mag = 100x
MAD median absolute deviation; robust spread: sigma = 1.4826 x MAD
Mask per-pixel flags (saturated, dead, cosmic ray, ghost...)
Matched filter smoothing with the expected source shape to lift faint sources out of noise
MPC Minor Planet Center: the official keeper of asteroid observations
Normalisation putting stamps in units of their own noise: (x - median) / (1.4826 MAD)
Null test repeat the search on data where there is nothing to find (shuffled times) to measure false alarms
Opposition asteroid opposite the Sun: brightest, most numerous
Overfitting learning the noise of the training set
Precision / recall / FPR purity of what is flagged / share of real objects kept / share of bogus wrongly flagged
PSF point spread function: the blur shape of a point source
Reference image deep picture of the same sky built from old exposures
Regularisation any device that discourages overfitting (L2, dropout, early stopping, subsampling)
ROC / PR curve recall vs false-positive rate / precision vs recall
Scoreboard one function that computes every headline number from the deployed pipeline
Sigma the typical size of the noise; "5 sigma" = 5 times it
SkyBoT / JPL Horizons services that predict where known asteroids are (Horizons is more accurate)
SNR signal-to-noise ratio: flux divided by its uncertainty
Stamp (triplet) 3 x 31 x 31 cut-out: science, reference, difference
Shift-and-stack shift frames to follow a trial motion, then add them
Tracklet a set of detections that line up as one moving object
Unit one field + CCD + quadrant + night
WCS the mapping between pixels and sky coordinates (RA, Dec)
XGBoost a fast gradient-boosted tree library
ZTF Zwicky Transient Facility, a survey telescope at Palomar Observatory
